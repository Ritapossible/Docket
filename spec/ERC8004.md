## What Docket uses

### Identity

Identity is an ERC-721: the token ID is the agent's identifier and the token URI points to an
off-chain agent card. Docket registers **one identity per mandate**, and the card names the
mandate address so that the identity and the enforcement it is scored on are the same object.

```solidity
function register(string agentURI, MetadataEntry[] calldata metadata) external returns (uint256 agentId);
event Registered(uint256 indexed agentId, string agentURI, address indexed owner);
```

Metadata entries Docket sets:

| Key | Value |
| --- | --- |
| `docket:mandate` | the mandate address |
| `docket:chainId` | the chain the mandate lives on |
| `docket:specVersion` | `DCS-1` |
| `docket:deployBlock` | the block the mandate was deployed in |

`docket:deployBlock` is not decoration. Public RPCs cap `eth_getLogs` by block range - Monad's
testnet endpoint allows 100 blocks per request - so a verifier scanning from genesis would need
hundreds of thousands of requests. Without a published start block, "anyone can recompute this"
is true in principle and false in practice, which is the same as false.

### Reputation

```solidity
function giveFeedback(
    uint256 agentId, int128 value, uint8 valueDecimals,
    string calldata tag1, string calldata tag2, string calldata endpoint,
    string calldata feedbackURI, bytes32 feedbackHash
) external;
```

A DCS-1 publication maps onto it as:

| Field | Value |
| --- | --- |
| `value` | the score, 0-1000 |
| `valueDecimals` | `0` |
| `tag1` | `docket:dcs-1` |
| `tag2` | the block height the score was computed at, decimal |
| `endpoint` | the mandate address |
| `feedbackURI` | where the recompute inputs are published |
| `feedbackHash` | the DCS-1 `inputHash` (`spec/DCS-1.md` §6) |

## Where Docket differs from the standard's intent - and why that is the point

ERC-8004's reputation registry is built for **client feedback**: a counterparty who dealt with
an agent posts a value and a tag. That is a review. Reviews are subjective, solicitable, and
worth roughly what reviews are ever worth.

A DCS-1 entry is a different kind of claim in the same slot. It is not an opinion about the
agent; it is a **deterministic function of enforced behaviour**, published by whoever ran the
indexer, and independently recomputable by anyone from the mandate's own event log. The
`feedbackHash` is what makes it checkable: it commits to the exact event set consumed, so a
reader can re-derive the number rather than trust the publisher.

The standard leaves the provenance of a feedback value entirely open. Docket fills that gap,
and that - not the registry plumbing - is the contribution.

Two consequences worth stating plainly:

- **Anyone can post a competing DCS-1 entry for the same mandate.** That is fine and intended:
  they should all agree, and a disagreement is evidence that someone's indexer is wrong. The
  spec, not the publisher, is the authority.
- **A DCS-1 value is not comparable with an ordinary client-feedback value** even though both
  land in the same registry. The `tag1` namespace exists so a reader can tell them apart, and a
  consumer that averages the two together has made a category error.
